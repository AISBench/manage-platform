## Registration module exports (agent)
verifiedIdentity(db,profile) -> raw identity row; profile {githubId,login,name,avatarUrl,type:'User'} verified on server. Never create Member here.
createRegistrationSession(db,res,identityId,config) -> {token_hash,identity_id,csrf,expires_at}; random32bytes hash, cookie triage_registration HttpOnly Secure per config SameSiteLax30min absolute. No import auth to avoid circular deps.
readRegistrationSession(db,token) -> {session,identity}|null. Return only valid expiry, not privilege.
getRegistrationStatus(db,identityId,now=Date.now()) -> {identity:{githubId,login,name,avatarUrl},application:null|PublicApplication,memberStatus:null|'active'|'pending_activation'|'disabled',canApply:boolean,canLogin:boolean,reapplyAt:string|null,blocked:boolean}. Never internalNote/reviewer details. canLogin if member non-disabled, blocked if disabled. Approval does not upgrade restricted session.
submitApplication(db,identityId,{displayName='',module='',reason,consent:true},{requestId=null,now=Date.now()}={}) -> PublicApplication. Validate strict values; actual API zod rejects unknown fields. Policy enabled, active queue < max, existing member409/disabled403, one pending409, rejection cooldown429. Reason10..2000chars, names/module<=120. Consent explicit true. Store no member until approval.
listJoinRequests(db,{status='',q='',page=1,pageSize=20}={}) -> {requests:AdminApplication[],total,page,pageSize,pendingCount}.
reviewApplication(db,id,{version,decision:'approved'|'rejected',publicFeedback='',internalNote=''},{actorId,requestId=null}) -> AdminApplication. Verify admin fresh INSIDE transaction, pending/version, reject requires publicFeedback1..500, note<=2000, approved default member. Use immutable identity only, reject disabled member409, preserve existing live role/status, create member pending_activation if absent. Exactly atomic member grant+request result+audit; no nested BEGIN. Matching same-decision replay MAY409 or original but never duplicate grant. Different replay409. Expose no sensitive info to applicant.
getAccessPolicy(db) -> policy; updateAccessPolicy(db,{version,registrationEnabled,publicOverviewEnabled,reapplyCooldownHours,maxPendingRequests},{actorId,requestId}) -> policy, fresh admin/version inside tx, ranges cooldown1..720/maxqueue1..10000. Main route validates actual public visibility before enabling and protects async revocation.

members.createMember extends opts approvePendingRequest=false. If matching pending registration exists: false ->409 PENDING_APPLICATION, true -> same transaction creates member and marks request approved/audit linked. Manual preregistration should not silently approve; client checkbox confirmation. Existing duplicate fixed ID remains409; disabled is never reenabled. Do not import registration.js into members.js (avoid circular); reuse transaction-safe grant helper if needed for review.

PublicApplication={id,status,displayName,module,reason,submittedAt,reviewedAt,publicFeedback,version,round}. AdminApplication adds identityId,githubId,login,name,avatarUrl,internalNote,reviewer,memberId. Applicant may only query own via session, no arbitrary ID params.

## HTTP contract (main)
GET /api/session existing fields + {mode:'guest'|'applicant'|'member',applicant:RegistrationStatus|null,features:{registrationEnabled,publicOverviewEnabled}}. csrfToken=member or registration csrf else null. user existing normal SessionUser only for valid member. Demo no auto login. Fresh guest obtains no cookie and no DB session.
GET /auth/github?intent=login|register&returnTo=/workspace?... stores bounded safe same-origin return path in state; known member login unchanged; unknown verified GitHub identity -> restricted session and /join (no auto application), prior pending/rejected -> /join/status. Disabled403, never apply. Registered/approved limited session stays limited until a NEW OAuth login creates normal session.
POST /auth/logout allows member or registration with corresponding CSRF and clears both cookies/sessions.
Demo ONLY explicit entry POST /auth/demo/member {login:'demo-maintainer'|'reviewer-chen'|'demo-applicant'}; POST /auth/demo/applicant {}. Require exact Origin + X-Demo-Intent:1 (no CSRF because no guest session), reject in live404. Demo applicant identity githubId3001 login demo-applicant. Member choice works only if its actual membership exists and not disabled. No artificial approvals. Frontend shows clearly isolated demo controls (not real GitHub auth). /auth/github in demo will not simulate true external auth.
GET /api/registration/status -> RegistrationStatus (restricted session only, unknown query keys400).
POST /api/registration/applications {displayName,module,reason,consent:true} ->201 {application}; restricted CSRF, sameorigin, rate-limited identity and IP. GETstatus after approved includes canLogin:true but no member permissions.
GET /api/admin/join-requests?status=&q=&page=&pageSize= -> module result.
POST /api/admin/join-requests/:id/approve|reject {version,publicFeedback?,internalNote?} -> {request:AdminApplication}; admin+csrf fresh.
GET /api/admin/access-policy -> {policy,publicStatus:{available:boolean,reason:string,checkedAt:string|null}}.
PUT /api/admin/access-policy {version,registrationEnabled,publicOverviewEnabled,reapplyCooldownHours,maxPendingRequests} -> {policy}; turning public on needs fresh metadata check (same demo stub), saving false immediately revokes snapshot generation/cache. Recheck admin/session/version after awaits. Cannot cache privilege in UI.
POST /api/admin/members extends approvePendingRequest:boolean optional. Resolver profile adds pendingApplicationId|null so editor can require confirm if pending.
GET /api/dashboard adds stats.pendingApplications for admins only; operations status adds optional accessPolicy and pending count.
GET /api/public/overview no auth: {available,reason:'disabled'|'unverified'|'private'|'expired'|'no_snapshot'|'ready',demo,repo,repoUrl,dataUpdatedAt,visibilityCheckedAt,stats:{openPRs,closedPRs,openIssues,closedIssues}|null}. Return200 with unavailable shape but no data if failclosed.
GET /api/public/items?kind=pr|issue&state=open|closed|all&q=&page=1&pageSize=20 -> {available,reason,items:PublicItem[],total,page,pageSize,dataUpdatedAt}. Only allowlisted query keys; reject ownerMemberId,module,priority etc even if blank.
PublicItem ONLY {number,kind,title,state,author,labels:string[],createdAt,updatedAt,url,merged?:true}. No id/body/fixed user id/assignees/reviewers/CI/local metadata/extra properties. URL canonical constructed server-side to configured GitHub public repo + number, not arbitrary stored URLs. Counts from projection only. No network triggered by guest GET; no-store headers, explicit limits.

Frontend: root `/` public portal always even signed in (member entry link). `/workspace` member only else guest/join prompt (no member API fetch before session valid), `/join` `/join/status` applicant limited. Existing App Workspace retained behind member mode; new admin request+accesspolicy nav and pending badge, forms/409 reload. Applicant public reason not internal note, pending status poll30sec only visible. Existing profiles/roles unaffected. Demo root guest; explicit buttons "演示管理员登录" and "演示申请加入" for local tests; POST custom X-Demo-Intent1, reload /workspace or /join. Public page has no personal center. No client-authorized user IDs/roles.
