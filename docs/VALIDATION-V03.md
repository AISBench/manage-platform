# v0.3 注册审核与游客模式验证记录

日期：2026-11-11（Asia/Shanghai）。环境：Windows、Node.js 24.18.0、已安装的 Google Chrome。

## 1. 实现与数据迁移

依据 [注册与游客设计](REGISTRATION-GUEST-DESIGN.md) 实现：

- 匿名首页公开概览，不自动创建 Cookie 或成员会话，无个人中心。
- 独立公开投影、字段允许清单、规范 GitHub 原文链接、分页 / 查询允许清单，拒绝内部字段查询。
- 生产公开数据默认关闭；仓库固定 ID 和 public 状态核验、60 秒有效期、过期 / 私有 / 失败关闭、撤销批次。
- 完整数据抓取前后分别核验公开性；后置请求不能复用更早已开始的 metadata 请求；epoch 防止关闭后旧任务迟到发布。
- GitHub 验证后的 30 分钟受限申请身份、显式同意和申请、本人状态与反馈；不是自动注册成员。
- 管理员队列、通过 / 拒绝、公开反馈与内部备注分离、version 并发保护、默认普通成员、禁用绕过保护。
- 批准后的旧受限会话不能访问成员 API；必须重新 OAuth 登录 / 显式演示成员登录。
- 管理员预录入遇到同一申请时，需要再次确认并原子批准，不重复创建成员。
- 访问策略网页、注册开关、待审核容量、冷却、限流和安全站内返回路径。
- schema3 增量迁移，不破坏已有成员、角色、事务、绑定、通知与旧迁移能力。
- `/workspace` 成员入口与事务深链接，根路径改为公开门户，原成员功能继续回归。

在启动新演示之前，已通过 SQLite backup API 备份原演示数据库；备份位于忽略的数据目录，未提交仓库。演示中的审核记录和角色修改保留，不因重启重置。

### API / 单元安全覆盖

- 匿名公开请求不新增身份会话、不触发外部网络请求；不能读取成员数据或写接口。
- 公开响应和统计不包含 body、固定身份、assignee / reviewer、本地 owner / workflow / dueAt、模块、备注、通知或其他内部字段。
- 即使公开表 JSON 意外混入内部字段，响应边界仍重新构造允许清单和原文链接。
- 私有化、仓库不匹配、metadata 失败或过期不能回退私有历史；重新公开后必须新建完整投影。
- 通过前无成员，客户端传入 role / ID 被拒绝；申请 CSRF / Origin、单 pending、拒绝冷却和队列容量。
- 不同申请者只能查看本人；申请者收不到内部备注；受限 Cookie 从不被 requireUser 接受。
- 审批使用固定 ID、事务内实时管理员检查、版本冲突、整体回滚和默认普通角色。
- 旧成员不重复审核；用户名复用不继承身份；停用者不能重申请恢复。
- 访问策略开启前核验公开性，异步等待后再验管理员和版本；关闭撤销公开缓存和待发布代次。
- 现有飞书绑定代次、停用 / 解绑竞态、通知撤销、事务版本冲突、最后管理员和一致性备份继续通过。

### 浏览器覆盖

1. 匿名门户、公开搜索筛选、无隐式 Cookie、仅 session/public 请求，无个人中心；手机 390px 无文档级横向溢出。
2. 匿名内部深链接显示认证提示，不挂载成员工作区、不请求内部事务 API。
3. 显式模拟 GitHub 身份 → 填写说明 / 同意 → 提交申请 → 管理员审核 → 本人刷新 → 仍是受限会话 → 新成员登录后进入工作区。
4. 公开策略关闭立即不展示数据；重新开启准确显示尚无快照；管理员同步后恢复；审核 / 策略手机页面可用。
5. 管理员预录入成员的核验、编辑、启停、最后管理员保护、筛选与审计。
6. 批量分派、409 冲突刷新、事务深链接、规则、偏好、通知和旧移动导航。

## 3. 持久化演示真实浏览器联调

除隔离自动测试外，还在实际 `http://127.0.0.1:3210` 通过两个独立 Chrome 会话完成同样的申请 → 审批 → 刷新本人状态 → 明确重新登录流程。确认：

- 申请批准后，原申请者 session 仍为 applicant、user 为 null，内部审核备注不在返回数据中。
- 新登录后获得普通成员身份，而非管理员。
- 公开页策略关闭、重新启用无快照、管理员本地演示同步后恢复，均为服务端真实状态。
- 该流程仅使用明确标识的演示入口，没有外部 GitHub / 飞书操作。保留审批与成员历史，供用户复核。

## 4. 仍需正式环境完成的验收

- 真实域名 / 海外服务器、Docker / TLS、代理信任与限流、数据卷和备份恢复。
- 真实 GitHub OAuth App、权限与配额、目标仓库 visibility 接口、完整真实同步和 Webhook 投递。
- 真实飞书租户发布、成员可用范围、授权、机器人权限和个人实际收信。
- 注册资料 / 审核历史的组织保留要求、反滥用阈值、公开数据启用授权和外部监控告警。

本轮没有重新执行真实 GitHub 全量抓取，也不把模拟 OAuth / 模拟 metadata 当成线上真实联调成功。CI 运行后端自动测试与构建，不持有正式应用凭证。公开仓库变私有的周期检测存在延迟，已被访问者下载的数据无法召回；不承诺消息严格 exactly-once 或统一的 15 秒送达 SLA。
