## 3. 关键安全回归

- 未预录入或已停用的账号不能因环境白名单、同名 / 改名或客户端自报 ID 获权。
- 待激活管理员不作为最后管理员的替代；并发版本冲突不覆盖他人变更。
- 普通成员不能修改成员列表、查看团队通知、抢占 / 改派；预分派不伪造可达性。
- 旧数据核验失败、用户名复用、绑定冲突、审计写入失败时，迁移或状态变更整体回滚。
- 飞书 state 浏览器 / 会话 / 成员关联、单次消费、跨账号切换拒绝。
- 相同飞书 ID 解绑后重绑仍使用更高代次，旧测试不会激活新关联；解绑也撤销已开始交换 Token 的旧绑定意图。
- 发送器在每次外部请求之间重新读取事务、责任人、成员、绑定和规则；已取消任务不会在失败回调中被恢复为 pending。
- 外部已接受但随后撤销的消息记录明确审计边界，不承诺可召回或 exactly-once。
- GitHub canonical 分页、固定身份字段、HTTP 限流信息与 CI unknown / 限流区别均有回归测试；已使用数据库禁止切换到另一仓库，以免相同编号串库。
- 备份通过 SQLite backup API 包含已提交 WAL，拒绝覆盖既有文件；备份与数据库加入 Git / Docker 忽略规则。

## 4. 外部接口验证与限制

v0.1 已完成的真实 GitHub 读取快照保留在 [历史验证](VALIDATION.md)。本轮真实 GitHub 读取再次验证时，曾出现单请求 10 秒网络超时；超时没有被当作同步成功，也未写入演示 / 正式数据库。该步骤不发送飞书消息，不修改 GitHub。

随后将验证调用的单请求超时调为 30 秒复测，读取过程中仍出现网络连接失败（CI 状态查询阶段）；本轮不宣称真实全量同步重新通过，也不修改线上默认超时来掩盖环境问题。目标服务器上线前必须实测网络和配额。

所有 GitHub OAuth 身份回调、飞书 OAuth / 发信的自动回归均使用 mock，不等于真实应用已经授权；不把旧快照数字冒充当前实时状态。
